# Prediction causality review — 2026-09-29

No new future-frame dependency was found in the default held-ball paths across the six scoped files. One confirmed configuration flaw allows a negative temporal stride to read future graphs; there is no demonstrated effect on reported PR-AUC because the default stride is positive. The selected causality tests passed, and this audit ran no training.

## Finding: temporal window configuration

- **Negative temporal stride permits future-frame inputs.** `prediction/graphs.py:340–348` subtracts a configurable lag and checks timestamp equality against that same lag, without requiring it to be nonnegative. `prediction/gnn.py:128` accepts overrides without range validation; `prediction/cv.py:410–419` also accepts negative integer overrides. **Severity: low** under current defaults, with serious leakage if the setting is used. **Confidence: CONFIRMED by reading and running.** In an in-memory store of 100 consecutive grid rows, `steps=6, step_rows=-5` at anchor **t=3.0 s** selected **[5.5, 5.0, 4.5, 4.0, 3.5, 3.0] s**. **Suggested fix:** require positive integers for `steps` and `step_rows` at model construction and in the window API; add rejection tests for negative strides. **Related spec:** `Docs/Specs/05-prediction-model.md`, “Leakage rules” and “Temporal GNN” window definition; `Docs/Specs/07-evaluation.md`, reported model comparisons.
- **PR-AUC ranking/impact:** this is the only new finding. Default `step_rows=5` is safe, and no affected reported run was established. Future observations could materially improve ranking, but the effect was not measured; negative strides can also cause an out-of-bounds error near the end of the graph store, so successful completion of a full affected run is not established.

## Checked and found clean

- **Native-to-grid selection and staleness:** `prediction/resample.py:49–84` uses a backward as-of join within each period and a tolerance derived from declared native FPS. Future cadence does not determine staleness. Object joins use the selected native frame; event lookahead is confined to the label path. Related specs: `02-game-state-schema.md`, causal velocities and frame identity; `05-prediction-model.md`, “Resampling” and “Labels.”
- **Ball and player inputs:** `prediction/features.py:85–118`, `130–136`, and `200–220` use a held visible ball and backward differences between visible positions. `prediction/graphs.py:84–128` follows the same rule and does not consume native velocities potentially contaminated by ESTIMATED ball positions. Related specs: `02-game-state-schema.md`, `objects.parquet`; `05-prediction-model.md`, “Leakage” and “Frame GNN.”
- **Feature history:** `prediction/features.py:76–82`, `173–179`, `318–329`, and `345–435` use backward lags, trailing windows, and forward-only possession accumulations. No centered smoothing or backward filling was found. The documented v1 final-third rotation flaw is a feature-definition issue, not future-frame access, and is not counted as a new causality finding. Related spec: `05-prediction-model.md`, “Lead-time features.”
- **Temporal history with positive stride:** `prediction/graphs.py:336–381` restricts history to the anchor or earlier rows in the same match and period, rejects history across grid gaps, and rotates history using anchor information. `prediction/gnn_net.py:161–173` runs the GRU forward over that window with a fresh hidden state for each invocation. Related spec: `05-prediction-model.md`, “Temporal GNN.”
- **Batch independence:** `prediction/gnn.py:152–207` trims padding and restores prediction order; `prediction/gnn_net.py` uses masked node operations and LayerNorm rather than BatchNorm. Direct checks with unfitted frame and temporal networks gave batch-versus-alone differences of 0 and approximately **3 × 10⁻⁸**, respectively. Related spec: `05-prediction-model.md`, “Frame GNN” batching and normalization rules.
- **Degradation state:** `prediction/degrade.py:138–170`, `218–241`, and `275–395` use forward episodes, causal AR(1), keyed randomness, and a past-held visible ball. Timeline allocation can span a whole period without making earlier outputs depend on later observations. Scored-row masks affect reported statistics rather than degraded objects. Related spec: `05-prediction-model.md`, “Vision sensitivity test.”
- **Caches:** `prediction/features.py:636–676` and `prediction/graphs.py:179–225` separate raw/held caches and bypass caches for degraded runs. `prediction/resample.py:221–225` invalidates feature, graph, and inferred-state caches on resampling. No future-derived aggregation was found in these paths. Related spec: `05-prediction-model.md`, graph scale/cache notes, “Vision sensitivity test,” and “Inferred possession — Caches.”

- Ran **49 selected tests; all passed** from `tests/test_resample.py`, `test_features.py`, `test_graphs.py`, and `test_degrade.py`, selecting names matching `past or estimated or velocity or window or gap or cadence or scored_rows_change`. Disabled bytecode and pytest cache writes. These include future perturbation/truncation, ESTIMATED-position isolation, velocity, gap, and temporal-window checks.
- Reproduced the negative-stride window entirely in memory and checked batch/padding independence with unfitted networks. Did not run training, model fitting, or the full GNN test suite because its fixtures train models.
- Did not inspect every saved run configuration or establish cache provenance for historical runs. No numerical PR-AUC correction can be assigned to the finding from this audit.
- Upstream causality of provider VISIBLE positions and possession metadata, native velocity producers, and the inferred-possession state machine was not independently audited here. The scoped code's safe use of these inputs does not prove their upstream provenance.
- The intentional `ball_source=raw` path still exposes the already-known ESTIMATED-ball leak. It is documented as a diagnostic arm and is not counted as a new finding.
- Match grouping inside temporal windows was checked; a full audit of outer train/validation/test split orchestration was outside this causality scope. No project files were modified during the audit; this report is the only file added afterward.
