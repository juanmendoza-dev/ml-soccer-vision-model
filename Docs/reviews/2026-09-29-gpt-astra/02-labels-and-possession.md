# Labels and possession review — 2026-09-29

The inferred-possession implementation is past-only at its input boundary and preserves the provider run's labels, eligibility, alarm fields, and caches. The audit found one upstream look-ahead in attacking-direction assignment and two evaluation concerns: provider possession couples noisy targets to features, and future set-play outcomes affect which rows are scored. Findings below are ranked by likely impact on reported PR-AUC; their numerical effects were not measured by training or an ablation.

## Provider possession and target alignment

- **Provider possession couples features to noisy labels. Severity: med.** At `converters/pff.py:143`, event-derived possession is carried forward; `prediction/features.py:71` and `prediction/features.py:318` use that possession for rotation and possession age, while `prediction/labels.py:63` selects targets for the same team. An event-timed possession change can therefore change the target and several strong features simultaneously. **Concrete observed case:** in match 3853, period 1, grid possession changes away → home at 204.3 s and returns to away at 208.8 s; the away shot/goal occurs at 208.741785 s. The entire H=3 lead-up is labelled negative and oriented toward home's goal. An inferred arm tracking away during that interval would still be trained and scored against those negatives. **Confidence:** CONFIRMED by reading and inspecting the stored frames/events for the coupling and this mismatch; SUSPECTED for PR-AUC inflation or non-causal provider annotation. The converter itself carries annotations forward; this audit did not establish that PFF assigned possession using future information. **Suggested fix:** retain the paired provider-target comparison, but describe its delta as disagreement with provider targets rather than a pure measure of inference accuracy. Independently adjudicate pre-shot possession disagreements and report a sensitivity analysis on those cases before interpreting the delta as deployment cost. **Related specs:** `Docs/Specs/02-game-state-schema.md`, “Possession and ball state”; `Docs/Specs/05-prediction-model.md`, “Labels” and “Inferred possession”; `Docs/Specs/07-evaluation.md`, required comparison #6.

## Set-play masking and evaluation selection

- **Scored rows depend on a future set-play outcome. Severity: low on the current PFF data.** `prediction/labels.py:73` removes an eligible, currently non-set-play row if its possession team takes a non-open-play shot or goal within H. The otherwise identical lead-up remains scored if that later shot never happens. This follows the specification, but conditions PR-AUC on a retrospectively selected population and can selectively exclude high-scoring negatives; it is selection bias, not a mask entering model inputs. **Confidence:** CONFIRMED by reading and counting stored rows. Beyond the current-phase mask and all-estimated exclusion, the future-event mask removes **53 rows at H=5 and 48 at H=3**, from **1,977,432** otherwise eligible PFF rows. A large headline effect from this mechanism alone is unlikely, although its PR-AUC effect was not measured. **Suggested fix:** explicitly qualify the reported metric's population and add a sensitivity metric whose inclusion rule depends only on current/past state. Define the target for transitions into set plays before comparing those metrics; do not silently reinterpret excluded shots. **Related specs:** `Docs/Specs/05-prediction-model.md`, “Resampled frames and labels” and “Labels”; `Docs/Specs/07-evaluation.md`, “Metrics” / scored rows.

## Attacking-direction causality

- **Attacking direction reads the whole period. Severity: low expected impact on current matches; definite causality violation.** `converters/pff.py:252–257` computes the starting goalkeeper's whole-period mean x; `converters/pff.py:420` converts its sign into direction, and `converters/pff.py:430–431` writes that direction to every frame. Metadata is checked against the result rather than supplying the output direction. Future goalkeeper positions can consequently reverse earlier attacking-frame features in both possession arms. **Confidence:** CONFIRMED by reading and an in-memory counterexample: keeping the first goalkeeper x at −40 m, while changing only two later positions from −40 to +50 m, changes the period mean from −40 to +20 m and reverses the assigned direction. This audit did not establish a wrong direction or measurable PR-AUC effect in existing matches. **Suggested fix:** assign direction from known metadata, retaining the whole-period goalkeeper statistic only as a diagnostic. Add a converter-level prefix-invariance test that changes future goalkeeper positions and verifies earlier frame directions remain identical. **Related specs:** `Docs/Specs/02-game-state-schema.md`, “Coordinate system” and `frames.parquet`; `Docs/Specs/05-prediction-model.md`, “Leakage” and “Leakage rules.”

## Checked and found clean

- **Inferred state is causal given its input tables:** `vision/state.py:188` filters to visible objects; candidate selection is within each frame; `vision/state.py:215–225` processes frames chronologically; `vision/state.py:106–107` resets state at period boundaries. No future backfill or ESTIMATED-position input was found. Relates to specs 02 and 05.
- **The inferred arm swaps only model inputs:** `prediction/possession.py:61–73` joins by native `frame_id` and recomputes the flip; `prediction/features.py:639–653` passes the swapped team/flip into feature construction while retaining provider frame fields and labels. Null inferred possession is handled without dropping provider-scored rows. This is causal subject to the upstream direction issue above. Relates to spec 05, “Inferred possession,” and spec 07 #6.
- **The provider run is preserved:** `prediction/features.py:636–643` separates provider and inferred feature-cache paths; `prediction/features.py:668–679` returns features alongside the provider frame table. Focused tests verify unchanged provider features, labels, scored rows, and provider-cache bytes. Alarm fields remain provider values, as spec 07 #6 requires; this is not a fully live ball-state/possession evaluation.
- **Eligibility and masks are separated:** `prediction/resample.py:95–108` computes eligibility from current provider ball state and possession, and all-estimated status from current visibility. `prediction/features.py:639` supplies only time, possession, and flip to feature construction; label masks and set-play phase do not enter it. Provider annotations' own causal provenance remains unverified. Relates to specs 02, 05, and 07.
- **Current-phase masking covers unsuccessful set plays too:** `converters/pff.py:228–249` uses backward restart matching by period and team; `prediction/labels.py:70` masks the phase regardless of whether a shot follows. Future-event selection is the separate concern above. Relates to spec 02, “Shots, goals and set plays,” and spec 05, “Labels.”
- **Label event windows and adjudication are isolated:** `prediction/labels.py:45–48` implements (t, t+H], and grouping by period/team prevents cross-period targets. `converters/pff_events.py` uses later restarts to adjudicate goals, but those outcomes stay on the label side. Relates to specs 02 and 05.
