# Lead-time features (v2) on the LightGBM baseline (2026-09-28)

Does the baseline alarm earlier if it can see an attack *building*? `features_version = "2"` (05, "Lead-time features") adds 21 features over the last 2–5 s to v1's 29: ball progress, possession so far, carrier progress, counts near the box, and the defensive line. Same model, fixed parameters, frozen folds and τ rule, both horizons. Compared with `lgbm-held-2026-09-27` using `evaluation.compare`, and with `scripts/lead_time.py` for everything the report doesn't show. The model code ran at `c69be9c`. The run is stamped `09baf81` (saved after a later commit that only added the script).

    python -m prediction.cv --model lgbm --features-version 2 --horizons h5 h3 --run-id lgbm-v2-2026-09-28
    python -m evaluation.compare data/runs/lgbm-v2-2026-09-28 data/runs/lgbm-held-2026-09-27
    python scripts/lead_time.py data/runs/lgbm-held-2026-09-27 data/runs/lgbm-v2-2026-09-28 [--horizon h3]

## Findings
- **v2 doesn't help, and it's slightly worse on PR-AUC.** H = 5: pooled PR-AUC **0.287 vs 0.296**, v2 better on **0/5 folds** (mean Δ −0.009). H = 3: 0.294 vs 0.298, also 0/5. ROC-AUC is a hair better (+0.001, 5/5 folds at H = 5, 4/5 at H = 3). Brier is tied. Both are calibrated (H = 5 top decile predicts 0.185 and sees 0.184; the baseline had 0.186 and 0.185).
- **The p curve before shots doesn't move.** Median p on the same shots and rows (paired):

  | s before shot | shots | v1 | v2 |
  |---|---|---|---|
  | 5 | 1,028 | 0.051 | 0.048 |
  | 2 | 1,102 | 0.158 | 0.158 |
  | 1 | 1,135 | 0.225 | 0.229 |
  | 0.2 | 1,150 | 0.296 | 0.283 |

  20% of shots have p > 0.3 two seconds out, for both models.
- **No early-ranking gain either.** PR-AUC with only the positives whose shot is 2–3 s or 3–5 s away (every negative kept, base rate 0.005–0.009) is 0.063 / 0.057 for v1 and 0.062 / 0.056 for v2, with v2 better on 1/5 folds in each bin. Closer to the shot (0–1 s, 1–2 s) v2 is better on 0/5 folds.
- **Alarms: v2's budget didn't transfer, and at matched false alarms it catches fewer shots.**
  - At each fold's τ it catches **203 of 1,154 shots vs 174**, but at **4.56 false alarms per match vs 2.50**. τ picked on the inner matches (≤ 3 there) gave 5.67 / 5.08 / 3.62 / 5.54 / 3.00 on the held-out folds. compare's "miss rate: A wins 4/5" is at those unequal false alarm levels, so it isn't a win. The budget transfer failing is a finding in its own right: v2's high-p region shifts more between matches.
  - Matched false alarms (one τ grid over pooled OOF, descriptive, H = 5): at ≤ 3 per match v2 catches **127 vs 172**, at ≤ 2 96 vs 138, and at ≤ 5 189 vs 248. The two only meet at ≤ 12 (404 vs 401). At H = 3 they're about even (≤ 3: 162 vs 165).
  - **Lead time is unchanged and still short of 00's 2 s.** Median lead 0.68 s vs 0.71 s. These are medians over different sets of caught shots (203 vs 174), so they aren't a paired comparison. Shots with a lead of ≥ 2 s: **1 of 1,154 vs 3 of 1,154**. Both are effectively zero.
- **Gain moved to the new features by substitution, not new signal.** The v2 groups take 0.24 of the gain at H = 5: ball progress over 2–5 s 0.08, possession so far 0.07, defensive line 0.05, near the box 0.03, carrier progress 0.005. The carrier drops from 0.19 to 0.07 and defence from 0.13 to 0.06, because the correlated v2 features take their splits: `ball_dist_min_5s`, `poss_start_dist` and `def_line_dist` are in most folds' top six. The ranking doesn't improve, so this is the same information in another form. It doesn't say the carrier or the defence matter less. The sensitivity test's Phase 2 ordering (done on v1, which stays the baseline) is unaffected.
- **Why the lead stays at ~0.7 s** (a hypothesis, not tested here): across the whole τ sweep, from 2 to 12 false alarms per match, both models keep a median lead of 0.6–0.75 s. So lowering τ catches more shots but not earlier ones. Ranking rows 2–5 s before a shot above attacks that build the same way and don't end in a shot is what's missing. Summaries of the last 5 s of ball, carrier, line and box counts, measured this way, don't separate them. Per-player movement and interactions (the temporal GNN), or a different reading of 00's budget (lgbm review), are the remaining levers.

## Checks
- **Causal and ESTIMATED-free**, tested (`tests/test_features.py`): every v2 feature is unchanged when frames after t change, and when every ESTIMATED position is scrambled.
- **The flip:** a mirrored match with the teams swapped, possession flipping every 3 s and some rows with no team, gives identical v2 features on every row with a team. A hand-built 5 s window across a turnover and a no-team row checks each feature's value. Planting the bug of lagging after picking the anchor frame fails both tests.
- **v1 unchanged:** on all 64 games, v2's v1 columns equal the `features_v1_held` cache exactly.
- **Found on the way, left in v1:** `ball_final_third_s` flags each older row with its own flip. After a turnover it counts time the ball spent in the *old* attacker's final third, and rows with no team count toward +x. It's kept byte-identical so v2 − v1 is a clean additive test. It's documented in 05, and v2's `poss_final_third_s` is the anchor-correct version.
- **Caveat:** fixed parameters (05), not retuned for 50 features. Early stopping landed at 89–157 rounds (v1: 86–173). A subset or retuned variant chosen after seeing these outer folds would be selected on the evaluation folds (07), so none was run.

## What this means next
- **v1 stays the baseline** (`--features-version` default `1`). The v2 code, cache key and tests stay, so the temporal models can reuse the anchor-frame history helpers.
- The hand-feature half of the roadmap's "Lead time" item is done, with a negative result. The **temporal GNN** is the next attempt at lead time. It sees per-player tracks, which these summaries throw away.
- The `id_fragment` rerun that 05 and the sensitivity review tied to "the attack-building features" now waits for the temporal GNN only. v2 isn't adopted, so a rerun on it would measure a model nobody uses.
- 07's open question (does a short opposing possession end an alarm) is still not what limits the model: neither v1 nor v2 alarms early enough for it to matter.
