# 03 — Vision Pipeline

## Goal
Turn broadcast video into game state (02) for each frame.

## Inputs / Outputs
- **In:** video file (mp4), optional team rosters.
- **Out:** `match.parquet`, `objects.parquet`, `frames.parquet`, `players.parquet` in schema v0.4.

## Stages
0. **View gate** — decides per frame whether it's a usable match view, before any GPU work. Broadcasts cut to ads, studio, crowd and close-ups; detection on those wastes time and produces junk.
   - **Grass share:** downscale to 160×90, share of pixels in a green HSV range. Below `min_grass` (~0.3) → `other`. ~1 ms on CPU, every frame.
   - **Keypoints:** when stage 4 runs, fewer than `min_keypoints` (~4) pitch keypoints found → `other`, even if green (close-ups on grass, green ads).
     The last count holds until stage 4 runs again, so failures on keypoint frames add up across the frames between them. While `other`, a green frame gets a keypoint probe every `keypoints_every` frames (feeds the gate only, no homography), so a view comes back on grass and lines, not grass alone.
   - **Hysteresis:** switch to `other` after `off_after_s` (~0.5 s) of failing frames; back to `match` after `on_after_s` (~1 s) of passing frames. Causal: uses frames `<= t` only.
   - **While `other`:** stages 1–7 don't run. Game state still gets a `frames` row with `ball_state`, `possession_team`, `ball_carrier_id` and `view_polygon` null (02: can't decide → null), and no `objects` rows.
   - **Back to `match`:** reset the tracker (IDs don't survive a cut). Keep the team assignment fit; refit if the break was longer than `refit_after_s` (~120 s, e.g. half-time). A refit matches its clusters to the old ones by kit color, so `home_cluster` keeps pointing at the same kit.
   - **Replays pass the gate** (grass, valid keypoints) and get tracked as if live. See open questions.
   - Thresholds are config values, tuned on labeled broadcast clips.
1. **Detection** — YOLOv8 fine-tuned on players, goalkeepers, referees, ball. Start from Roboflow's pretrained soccer weights.
2. **Tracking** — ByteTrack (via `supervision`) for stable `object_id`s. People down to `track_min_conf` (~0.1) go to the tracker, whose second pass keeps existing tracks alive on weak detections; the ball and kit-color samples need `min_det_conf` (new tracks need ~0.35, inside supervision). A lost track is dropped after `lost_track_s` (~1 s) of wall time, whatever the frame skip.
3. **Team assignment** — SigLIP crop embeddings → UMAP → KMeans(k=2), as in roboflow/sports. Goalkeepers assigned by nearest team centroid.
4. **Pitch homography** — pitch keypoint model → per-frame homography → pixel to meters. Smooth over time to reduce jitter. Fits are accepted or rejected as in Pitch template → Homography acceptance.
5. **Ball tracking** — dedicated detector at higher input resolution; interpolate short gaps (< 1 s) and mark `interpolated=True`.
6. **Jersey OCR** — read numbers over multiple frames, vote per track, link to roster → `player_id`. Borrow approach from sn-gamestate.
7. **Velocities** — backward differences on trailing-smoothed positions (causal, frames `<= t` only; see 02 `vx, vy`). A centered window would leak future frames into the features.
8. **Game state inference** — fills `possession_team`, `ball_carrier_id`, `ball_state` and `view_polygon` (02). Works on pitch coordinates only, not pixels, so the same code runs on dataset tracking for testing.
   - **Ball carrier:** the player nearest the ball, within ~1.5 m, with ball height < ~1 m where known, for at least ~3 consecutive frames at 10 Hz. Otherwise null (loose ball, pass in flight).
   - **Possession team:** the carrier's team. It persists through passes and loose balls until a player from the other team becomes carrier. Null at the start of a period until someone first controls the ball.
   - **Ball state:** dead when the ball is past a touchline or goal line; dead while the ball is stationary at a restart spot (corner arc, penalty spot, touchline) with players set up; null when the ball hasn't been seen for > 2 s or there is no valid homography (replays, close-ups); otherwise alive.
   - **View polygon:** the four image corners projected through the frame's homography.
   - All thresholds are config values, tuned on dataset tracking (see acceptance criteria).
   - **Implementation** (`vision/state.py`, 2026-09-29). Everything above as one causal state machine, frame by frame: a frame's output uses that frame and earlier ones only, so it runs live and on dataset tracking alike. Thresholds are in seconds and meters, never frames, so any frame rate works. On dataset tracking it reads what vision would see: VISIBLE ball and VISIBLE players and goalkeepers (referees never), so PFF's ESTIMATED positions (later frames, 05 Leakage) never reach it.
     - **Candidate:** the nearest player to the ball on the frame, if within `carrier_radius_m` (1.5) and the ball's `z` is null or under `carrier_max_z_m` (1.0).
     - **Carrier:** a candidate becomes carrier after `carrier_min_s` (0.3) as the candidate. The streak survives frames without a visible ball for up to `carrier_gap_s` (0.5), and the carrier is held through them. It ends when another player or nobody is the candidate on a frame with a ball.
     - **Possession:** the team of the latest carrier. A carrier with no team (vision's unknown) doesn't change it. Reset to null at each period's start.
     - **Team near (`team_near_s`, off by default):** when set, the candidate's *team* being the same for `team_near_s` moves possession too, whichever of its players is nearest, with no carrier needed. The streak ends on a frame with a ball where the candidate is the other team, nobody, or a player with no team, and after a ball gap longer than `carrier_gap_s`. Off is `None`, which `StateConfig.to_dict()` leaves out, so the default config key (05 Caches) and earlier runs' `state_config` are unchanged.
     - **Ball state,** in order: null until the first visible ball of the period, or once the ball has been unseen for more than `ball_lost_s` (2); **dead** once the ball is out (more than `out_margin_m` (0) past a touchline or goal line; a ball that's out has no carrier); **dead** once the ball has been still (speed under `still_speed` 0.5 m/s) for `still_spot_s` (1) at a restart spot (within 2 m of a corner, the center spot or a penalty spot, or inside a goal area), or for `still_any_s` (1) anywhere outside the penalty areas (free kicks; inside them it's usually a keeper holding the ball, which is alive). Dead holds until the ball is in and moving at `kick_speed` (3 m/s) or more, which starts play again. Otherwise alive.
     - Ball speed is over the last `speed_window_s` (0.2) of visible sightings.
     - The defaults above were tuned on 8 PFF games (`Docs/reviews/stage8-2026-09-29.md`, which has the first values). Two dead-ball possession rules (out → the other team, possession frozen while dead) were tried and dropped: both made agreement with PFF worse.
     - **Result on all 64 PFF games:** possession agrees on 77.9% of frames (82.9% alive), under the 90% target; a confirmed carrier's team agrees 97.9% of the time, but only 26% of alive frames have one. Dead frames come out dead or null 89.9% of the time, but only 6.7% dead (most have no ball in the data); alive frames come out alive 81.0%. Whether that's good enough is decided by 07 #6, not the target: **it isn't yet** (2026-09-29). The same LightGBM on stage 8's possession loses 0.038 PR-AUC (5/5 folds). It collapses on the 14% of rows where stage 8 names the other team, where shots follow PFF's team about 3× as often as stage 8's, and it's a little worse where they agree too (`Docs/reviews/possession-inferred-2026-09-29.md`). Giving the model stage 8's carrier age, or making possession unknown past 10 s without a carrier, recovers none of it (`Docs/reviews/possession-stale-2026-09-29.md`), so the rules themselves change next. 85% of the disagreeing rows are PFF changing possession while stage 8 hasn't followed. Disagreement is 55.6% in the first second after PFF's change, and 30.5% of rows with no visible ball vs 8.7% with one.
   - **Learned possession (proposed 2026-09-30, not built).** This replaces the short draft. Strict nested training is required from the first run; plain out-of-fold training of the outer training matches is not an option. The implementation waits for spec review. No schema change: possession still uses 02's `possession_team`; carrier and ball state use their existing fields. Features, probabilities and fit provenance below are internal caches, not additions to schema 0.6.

     **Why this model.** Faster proximity rules (`carrier_min_s = 0.1`, `team_near_s = 0.05 / 0.1 / 0.2`) failed the scored-row bar. They cut first-3-s disagreement by about 15% but doubled positive-row disagreement from 7.8% to about 15% by following defenders' brief touches. Hand rules on proximity stop here. Team shape and motion over the last second may distinguish a turnover from a touch; that is the hypothesis, not an established result. The default rule costs −0.038 PR-AUC at H = 5, worse on 5/5 folds (07 #6). Carrier age and unknown possession past 10 s recovered nothing. See the stage 8, inferred-possession and stale-possession reviews dated 2026-09-29.

     **Model and label.** One LightGBM binary classifier, raw output `q = P(home has the ball)`, per valid 10 Hz grid row. The emitted probability `p` is symmetrized below. Train on PFF `possession_team`: home = 1, away = 0. Select rows whose PFF `ball_state` is alive, possession is home/away, and `all_estimated` is false. `all_estimated` has 05's exact meaning: no player/keeper has visible true, irrespective of team or finite coordinates. Vision derives it from native objects; a parity check must match the resampler. Keep set plays; do not use shot masks or a shot horizon to choose possession training rows. Give each original row weight 1; its mirror also has weight 1. No class weights or match balancing.
     - PFF `ball_state` only selects training rows. Neither it, PFF possession, carrier, set-play flags, events, shot labels, match ID nor period number enters the feature matrix. Match and period identify boundaries and joins only; attacking direction normalizes coordinates.
     - PFF's own lag is learned too. That is accepted because the downstream labels and 07 #6's scoring use PFF possession. Agreement measures reproduction of that convention, not exact physical control. PFF's lag still caps what the comparison can establish about live accuracy.
     - Copy the fixed baseline values from `prediction/lgbm.py` into the vision implementation; do not import prediction: binary objective/log loss, learning rate 0.05, 31 leaves, minimum 500 rows per leaf, feature fraction 0.8, bagging fraction 0.8 every round, L2 1, max bin 255, deterministic true, force column-wise true, verbosity −1, seed 20260927. CPU, `num_threads = 4` fixed for timing and reproduction. No parameter search. The correlated 10 Hz rows justify the same conservative leaves as the baseline.
     - At most 2,000 rounds, stop after 100 rounds without validation log-loss improvement. For each allowed training-match set T, sort its match IDs, select `round(0.15 * len(T))` with NumPy `default_rng(20260927).choice(..., replace=False)`, and hold those whole matches out for early stopping. This is the baseline's procedure, independent of shots. Mirror after splitting, so both copies stay together. Refit on all T for `max(1, best_iteration)` rounds. Store the probe's training/validation IDs and refit's IDs. Abort if either side has no eligible rows.      **Time and visibility contract.** Feature extraction reads schema 02 native frames, sorted by `(period, timestamp_s, frame_id)`. A usable object has `visible = True` and finite x/y. Referees never count. Players include `player` and `goalkeeper`; outfield means `player` only. Team is stage 3's home/away/null assignment. `object_id` may link a track or break a distance tie, but is never an input column. `player_id`, provider vx/vy and ball z are never read by this extractor. Provider velocities can include ESTIMATED positions even on a visible row (05 Leakage).
     - The learned path runs a separate copy of the default rule on these usable native objects with every z forced to null and both `team_near_s` and `possession_model` set to None (no recursive learned call). Its rule possession, candidate, carrier and ball state cannot indirectly expose height. The learned switch changes only possession; carrier, ball state and age remain this copy's outputs. The historical rule path, including its height gate, stays unchanged for old runs and the comparator. Call this the **2D rule** below. Never feed learned possession back into the 2D rule.
     - Grid: 05's per-period `t_s = k / 10`, latest native frame at or before t, skip if older than `1.5 / native_fps` seconds; integer microseconds for comparisons. Vision implements this from 02, with parity tests against resampling; it does not import `prediction.resample` or read its attacking coordinates. Prediction supplies/checks only the grid keys at the bridge.
     - A native gap longer than `1.5 / native_fps` starts a new feature-history segment. A skipped grid point also breaks grid history. Reset ball/contact/motion histories at either gap and at period starts; never interpolate across them. The 2D rule retains its existing period reset and ball-gap behavior across missing frames; its possession and carrier age may therefore outlive a feature segment. This is intentional rule state, not a filled position. Never invent intermediate native frames.
     - On missing-object frames, the current player sets are empty. Ball position may be held for at most 1 s, as in 05's held ball; age continues until the feature segment ends. Player positions are never held. No fresh contact is inferred from a held ball.
     - Let `d = +1` when home attacks positive x, else −1. Normalize each period with `X = d*x`, `Y = d*y` (a 180° rotation when d = −1); home attacks +X. Distances are Euclidean pitch meters. For team a, `s_home = +1`, `s_away = −1`. All coordinates below remain in this home frame; “toward own goal” is longitudinal `−s_a * VX`, positive when retreating. This fixes the wording of the earlier draft, which said attacking goal; it carries the same information with the opposite sign.

     **Exact input columns.** Compute the following 39 scalars at each valid grid time t. Missing numeric values are NaN, passed to LightGBM without imputation, scaling or clipping. Team codes are home = +1, away = −1, unknown = 0 (numeric, not categorical). Flags/counts are unitless. Times are seconds. The model matrix is Float32, in the listed order; probabilities are Float64. No additional columns enter the model.

     | group / columns | definition and source |
     |---|---|
     | `rule_team`, `rule_carrier_age_s`, `rule_candidate_team` (3) | 2D rule at the selected native frame u. Age is `u − last native time with non-null rule carrier` in this period, 0 while carried, NaN before the first carrier (05). Candidate is the current candidate within 1.5 m, using the rule's out-of-bounds check and object-ID tie break; 0 when the ball/candidate/team is absent. Do not expose a stale candidate on a ball-missing frame. |
     | `ball_seen`, `ball_age_s`, `ball_x`, `ball_y` (4) | Seen = 1 only for a usable ball on u. Choose the lowest object_id if multiple balls exist, as `infer` does. Let b be the last usable native ball time in this feature segment, at or before t. Age = t − b, NaN before any sighting. X/Y are that sighting's position if age ≤ 1 s, else NaN. Seen is 0 without a ball. |
     | `ball_vx_02`, `ball_vy_02`, `ball_vx_1`, `ball_vy_1` (4) | For W = 0.2 / 1 s, first and last usable native ball sightings in `[t−W, t]` within the segment: `(X_last−X_first)/(u_last−u_first)` and likewise Y, m/s. Require the ball seen on u, span ≥ W/2, and no interval between successive sightings > 0.5 s. Otherwise NaN. W/2 rejects jitter-only spans; 0.5 s is the existing carrier-gap tolerance. Only visible endpoints enter; no provider velocity. |
     | `near_home_m`, `near_away_m` (2) | Minimum 2D distance from the usable ball on u to a usable player/keeper of that team on u. NaN without either. No radius cap, no held ball. Unknown-team players do not join either team. |
     | `nearest_<team>_<window>_<reach>` (8) | team = home/away, window = `05` / `1` (0.5 / 1 s), reach = `any` / `r15`. Native-time share, defined below, for that team being nearest at any distance or within 1.5 m. |
     | `<team>_centroid_x` (2) | Mean X of all usable players/keepers on u assigned to that team, m; NaN if none. |
     | `<team>_mean_vx_own` (2) | Mean `−s_team * VX` over that team's usable players/keepers on u with a valid native velocity, m/s. Recompute VX from the first and last usable sightings of the same object_id in `[u−0.2, u]`; require span ≥ 0.1 s, same team throughout, and usable sightings on every intervening native frame with no native gap. Otherwise that track has no velocity. NaN if none qualify. |
     | `<team>_past_halfway` (2) | Count usable outfield players on u with `s_team * X > 0`; 0 if none. A player exactly on halfway does not count. |
     | `<team>_highest_x`, `<team>_deepest_x` (4) | Max / min X among that team's usable outfield players on u, m, NaN if none. Both are in the home frame: away's highest attacking position is its minimum X. Goalkeepers are excluded so they cannot define the outfield line. |
     | `<team>_visible_n` (2) | Count all usable players/keepers on u assigned to the team; 0 if none. Unknown-team players count for the fallback condition but neither team's shape. |
     | `diff_<shape>` (6) | Home minus away for each of the six shape scalars above: centroid_x, mean_vx_own, past_halfway, highest_x, deepest_x, visible_n. NaN if either operand is NaN. |

     Native contact shares: on each native frame, find the nearest of **all** usable players/keepers to the usable ball. No ball/player gives both teams weight 0. Ties within 1e−9 m split weight equally across the distinct tied team values (home, away, unknown); unknown's share is credited to neither. For `r15`, also require minimum distance ≤ 1.5 m. Hold these weights from native time u to `min(next native time, u + 1.5/native_fps, t)`; a missing-ball/player frame contributes zero. Integrate each team's weight over `(max(segment start, t−W), t]`, divide by the duration of that interval, including unknown/unseen time. Zero duration gives NaN. This is elapsed-time share, not a count biased by native fps, and uses no frame after t. The 0.5 / 1 s windows capture brief contact versus sustained control.

     Append **all 39 features again** at exact grid times t − 0.5 s and t − 1 s, suffixes `_lag05` and `_lag1`: **117 input columns total**, ordered table-first then the two complete lag blocks. Read the already computed past grid vector; do not recompute it with later information or replace a missing lag by the nearest row. A missing lag or any skipped grid point/feature-segment boundary between it and t makes the entire lag block NaN. At period starts, current features use available history and missing lags remain NaN. Native frames between grid points feed the rule, ball, contact and velocity features even though only grid rows are learned/scored. No shot mask interrupts histories.

     **Symmetry and output.** Every training and early-stopping row also appears under transform M: negate X and VX, leave Y and VY unchanged, swap home/away and flip the label. This is a left/right pitch reflection plus a team swap, after direction normalization, not a change to schema coordinates. Apply it to the whole causal history. Team-coded features negate; distances/shares/counts swap; centroids swap and negate; new home highest/deepest = negative old away deepest/highest (and vice versa); own-goal velocities swap without negation. Recompute every home-minus-away difference, and transform every lag block the same way. NaNs and ages stay NaN/unchanged.
     - Augmentation alone does not force tree symmetry. Emit `p(x) = (q(x) + 1 − q(Mx)) / 2`, two predictions from the same booster, for offline and live. Thus `p(Mx) = 1 − p(x)` to floating-point tolerance; no second trained model. No probability calibration, tuned margin, smoothing, minimum dwell or hysteresis in v1.
     - Possession = home if p ≥ 0.5, away otherwise. Exactly 0.5 goes home; the probability symmetry test must not demand opposite hard labels at that tie. If there are no usable visible players/keepers on the current native frame, keep the 2D rule's possession (including null) and record p as null plus `fallback = True`. Unknown-team visible players still allow model inference. Never substitute provider possession on a missing result or artifact; fail instead. Carrier, ball state and carrier age remain the 2D rule's, regardless of the predicted team.
     - Score every valid grid row, not just PFF-alive/training rows; labels only determine fitting and later scoring. In live mode, run the same 10 Hz clock causally and hold the latest learned possession between ticks. Before the first valid tick, or on a current frame with no usable players, use the rule. Reset the held learned output on a period start or grid gap. The existing view gate still emits null on `other` frames.

## Requirements
- Runs on M1 with `--device mps` for short clips; RTX 2060 for full matches.
- Configurable frame skip for detection (tracker fills gaps).
- Stage 0 runs on every frame, including skipped ones, so a cut is caught within `off_after_s`.
- Every stage can cache its output so later stages rerun without redoing detection.

## Streaming API
One stateful object, one frame at a time. Offline is a loop over it, so live (soccer-live-overlay) and offline share code, and every stage is causal by construction.

    pipe = VisionPipeline(config, stages)
    for frame_id, t, image in video:
        vf = pipe.step(frame_id, t, image)      # VisionFrame
        writer.add(vf)                           # game state (02) + caches
    writer.close()

- `VisionFrame`: `frame_id`, `t`, `view` (stage 0), `homography_ok`, `objects` (object_id, class, team, pitch x/y or null, confidence, `tracked_only`, display box), `ball` (same, or null), `view_polygon`.
- Stages are injected (detector, tracker, team assigner, keypoint model), so tests run with fakes and live mode can swap in smaller models.
- Live forms of stages that are batch-style in roboflow/sports:
  - **Teams:** fit on a warmup window (the first `team_warmup_s` of `match` frames), then assign. `team = null` until fitted.
  - **Ball gaps:** extrapolated forward from the last velocity, `interpolated=True`, never filled from later frames. History older than `ball_max_gap_s` is dropped before a new detection uses it (no velocity measured across a gap), and the ball isn't extrapolated while the homography is invalid or after a detection that has no pitch position.
  - **`visible`:** detections are visible. A filled-in box (tracker fill or ball extrapolation) that has drifted entirely out of the frame is written `visible=False` (it's already `interpolated=True`, 02).
  - **Homography:** smoothed over a trailing window only, and only across fits that agree with each other (no averaging across a camera cut).

## Pitch template
The keypoint model is roboflow/sports' `football-pitch-detection` (32 keypoints). Its template (`SoccerPitchConfiguration`) is 120 × 70 m in centimetres, origin at a corner, y growing toward the near touchline, with a 20.15 m deep penalty box. We keep its **keypoint order** (that's what the weights predict) but put each landmark at its **real** position in 02's frame: meters, center origin, 105 × 68, penalty area 16.5 × 40.32, goal area 5.5 × 18.32, penalty spot 11, center circle 9.15. The homography then outputs 02 coordinates directly, nothing gets rescaled.
- Keypoint 1 (roboflow `(0, 0)`) is the far-left corner as seen on TV → `(-52.5, 34)` in the TV frame (+x right, +y toward the far touchline, as in 02).
- Keypoints 9 / 22 (penalty spots) → `(∓41.5, 0)`; 31 / 32 (center circle on the halfway line) → `(∓9.15, 0)`.
- The corner assignment is read from roboflow's radar drawing (y down = toward the camera). Check it on the first real clip: the center spot and a penalty spot should land where they are on screen.
- Keypoints below `min_keypoint_conf` are dropped; at least 4 are needed for a homography (stage 0 counts them).

### Homography acceptance
The first 2060 smoke test (`Docs/reviews/smoke-test-2026-09-27.md`) put objects more than 15 m off the pitch. When a fit can't be trusted, positions go null. They are never clamped or guessed. All thresholds are in `VisionConfig`, and they are guesses until they're tuned on real clips.
- **Per fit:** RANSAC at `ransac_m` on the template. A fit needs `min_inliers` inliers and a mean inlier reprojection error ≤ `max_homography_err_m`. Stage 0 still gets the count of confident keypoints, not inliers. Four inliers always fit exactly (error 0), so the next two checks are what catch a bad four-point fit.
- **Across fits:** a new fit is compared with the one in use at its own inlier keypoints. If the mean distance is ≤ `max_homography_jump_m`, it joins the trailing average. If not, it waits and the homography isn't ok until the next fit. If that next fit agrees with the waiting one, the camera changed and the two start a new window. If it agrees with the old one, the waiting fit is dropped. Once the fit in use is older than `homography_max_age_s`, any fit that passes the per-fit checks is taken. Frames already emitted are never rewritten.
- **Per position:** a projection more than `max_off_pitch_m` (10 m, under the validator's 15) outside the lines, or not finite, gets null x/y. The detections cache keeps the row, with `homography_ok` true and a null `pitch_x`. An extrapolated ball that crosses that bound is dropped, and its motion is forgotten. Genuine out-of-play balls within the margin are kept for stage 8.

## Teams and direction
Clustering gives cluster 0 / 1, and the homography gives the TV frame. 02 needs `team` as home/away and +x toward the goal home attacks in period 1. Two config inputs:
- `home_cluster`: which cluster is home (picked from sample crops at warmup, or a flag). Until set, `team = null`. Never guessed.
- `home_attacks_tv_right_p1`: if false, positions are rotated 180° (x → -x, y → -y) for the whole match, so +x is always home's period-1 attack. `home_attacks_positive_x` is true in odd periods, false in even ones.
- Later: infer direction from which end each team's goalkeeper stands at during warmup.
- `period` and the period start come from config too (live: set at kickoff and half-time).

## Display output (pixel exception)
Pixels never leave `vision/` as data, but the live overlay draws rings on the video, so it needs screen positions. The one exception: `VisionFrame` carries each object's box as fractions (0–1) of the frame, for **display only**. Same status as the detections cache below, which 08's debug mode draws from. Game state, prediction and evaluation never read it.

## Diagnostics
Debugging works from cached data after the run, not from extra logging during it. Nothing here adds work to the inference loop beyond writing the cache.

## Acceptance criteria
- Output passes the schema validator in `tests/`.
- On SoccerNet-GSR validation clips: positions within ~2 m for most visible players (measure with sn-trackeval GS-HOTA as a secondary metric).
- Team assignment correct on > 95% of player-frames on sample clips.
- Stage 8, run on PFF, SkillCorner and IDSSE tracking and compared to provider values: possession team matches on ≥ 90% of frames where the provider has a value; frames the provider marks dead are labeled dead or null ≥ 90% of the time. Starting targets; revisit after the first run. First run (PFF, 2026-09-29): 77.9% and 89.9%, and the dead-or-null share is nearly all null, so it's read with dead → dead and alive → alive beside it (Stage 8 above).

## Open questions
- Is Roboflow's pretrained ball detector good enough, or is ball fine-tuning needed?
